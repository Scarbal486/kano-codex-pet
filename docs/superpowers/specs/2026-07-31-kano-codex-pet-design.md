# 鹿乃 Codex 宠物设计规范

状态：已批准  
日期：2026-07-31  
目标仓库：`Scarbal486/kano-codex-pet`（初始为私有仓库）

## 1. 项目目标

制作一套可安装到 Codex 桌面端的鹿乃自定义宠物。宠物采用鹿乃无印时期的鹿角少女形象，严格复现本地 32 张静态表情图的圆润 Q 版画风，并提供完整、真实的逐帧动画，而不是重复静态帧。

最终宠物必须：

- 使用 Codex Pet v2 图集规范。
- 在 192×208 的显示单元中保持清晰、稳定的角色辨识度。
- 包含 9 个标准动作状态和 16 个顺时针环视方向。
- 通过结构验证、透明度验证、动作预览、方向语义检查和本机安装验证。
- 在用户检查最终联系表和动画预览后才视为完成。

## 2. 范围与非目标

### 范围

- 建立鹿乃角色母版和画风规范。
- 为 9 个标准状态制作完整逐帧动画。
- 为 v2 制作 16 个方向姿势。
- 生成 `pet.json`、`spritesheet.webp`、验证报告、联系表和逐状态预览。
- 安装到本机 Codex 并验证实际播放。
- 创建私有 GitHub 仓库和可下载的私有 Release。

### 非目标

- 不制作独立 Windows 桌面宠物应用。
- 不混用花寄鹿、鹿乃まほろ、情书或 MKLNtic 的服装与外貌。
- 不把根目录中的 32 张原始参考图提交到 Git。
- 不在本阶段公开仓库或自动向社区宠物库投稿。
- 不在未核验素材权利前授予角色资产的公开再分发许可。

## 3. 资料依据与人设边界

设计依据按优先级排列：

1. 本地 32 张鹿乃静态表情图，作为外观、线条、颜色和表情的视觉正典。
2. 萌娘百科“鹿乃”和“鹿乃樱帆”条目，作为身份与行为参考。
3. 用户提供的人设整理稿，仅将可核验或与现有表情一致的内容用于动作设计。

已确认并可用于宠物表现的特征：

- 温柔、治愈、天然萌，略带调皮或小腹黑。
- 萌系唱见身份，生日为 12 月 24 日。
- 喜欢蛋包饭、MMO 和益智游戏，讨厌打针。
- 游戏状态可作为“任务进行中”的行为隐喻。

未在上述两个条目中确认的“关西腔、薄声带、害羞、音乐是魔法、哥哥启蒙”等信息不主导本项目的动作或文案。它们只有在补充可靠来源后才可升级为正式设定。

资料入口：

## 4. 视觉身份

宠物采用“鹿乃（无印）/唱见鹿角少女”形象：

- 棕色圆润短发和整齐刘海。
- 小型浅色鹿角。
- 蝴蝶结固定在角色右侧；角色转向时仍必须保持真实佩戴侧，不能因简单镜像换边。
- 红色长围巾。
- 绿色白圆点服装和浅色内搭。
- 大颗深蓝眼睛、柔和腮红和圆润脸型。
- 大头、小身体、短手脚的 Q 版比例。

从参考图提取的核心颜色：

| 用途 | 颜色 |
| --- | --- |
| 头发 | `#BD8068` |
| 围巾 | `#EB435C` |
| 绿色服装 | `#AAD67C` |
| 肤色 | `#FFEBD3` |
| 蝴蝶结与腮红 | `#ED8C87` |
| 鹿角与浅色高光 | `#FFFCEF` |
| 眼睛深色 | `#013251` |
| 蓝紫轮廓 | `#343363` |

画风要求：

- 使用圆润、稳定的蓝紫色粗轮廓。
- 以平涂为主，只允许少量柔和阴影。
- 表情夸张但保持可爱，不转向写实或复杂插画质感。
- 动作主要依靠姿势、表情和轮廓变化表达，不依赖文字或漂浮特效。

下列问题一旦出现即判定整行失败：

- 变成粉发、双马尾或花寄制服。
- 蝴蝶结换边、鹿角数量或形状变化。
- 脸型、刘海、眼睛颜色、围巾或圆点服装漂移。
- 变成像素、3D、油画、塑料玩具或写实风格。
- 不同行之间线宽、比例或渲染方式明显不一致。

## 5. Codex Pet v2 规格

最终图集为 8 列 × 11 行，每格 192×208，完整尺寸为 1536×2288。`pet.json` 必须包含 `spriteVersionNumber: 2`。

| 行 | 状态 | 有效列 | 时间或方向 |
| --- | --- | ---: | --- |
| 0 | `idle` | 0–5 | 280, 110, 110, 140, 140, 320 ms |
| 1 | `running-right` | 0–7 | 每帧 120 ms，末帧 220 ms |
| 2 | `running-left` | 0–7 | 每帧 120 ms，末帧 220 ms |
| 3 | `waving` | 0–3 | 每帧 140 ms，末帧 280 ms |
| 4 | `jumping` | 0–4 | 每帧 140 ms，末帧 280 ms |
| 5 | `failed` | 0–7 | 每帧 140 ms，末帧 240 ms |
| 6 | `waiting` | 0–5 | 每帧 150 ms，末帧 260 ms |
| 7 | `running` | 0–5 | 每帧 120 ms，末帧 220 ms |
| 8 | `review` | 0–5 | 每帧 150 ms，末帧 280 ms |
| 9 | 环视 A | 0–7 | 000° 至 157.5°，每次增加 22.5° |
| 10 | 环视 B | 0–7 | 180° 至 337.5°，每次增加 22.5° |

标准动作行末尾未使用的格子必须完全透明。两行方向格全部使用。000° 表示向上看，不表示正面中立姿势。

## 6. 状态行为设计

| 状态 | 参考锚点 | 动作设计 |
| --- | --- | --- |
| `idle` | 微笑 | 温柔微笑、呼吸、眨眼和轻微围巾摆动。 |
| `running-right` | 这就去 | 欢快向屏幕右侧小跑，围巾向后摆动。 |
| `running-left` | 这就去 | 单独补绘左移动画，不直接镜像，保持发饰佩戴侧。 |
| `waving` | 早上好 | 抬手、挥动、落下的亲切招呼。 |
| `jumping` | 阿里嘎多 | 蓄力、腾空张臂、顶点、下降、站稳。 |
| `failed` | 我看不懂 | 从困惑转为含泪和轻微泄气，不使用漂浮问号。 |
| `waiting` | 拜托了 | 双手合十、抬眼期待确认，带少量撒娇感。 |
| `running` | 打游戏中 | 坐着专注操作粉色掌机，表现任务处理中。 |
| `review` | 原来如此 | 轻微前倾和视线核对，最后露出理解后的表情。 |

16 个环视方向使用正面微笑作为身份基准，通过眼睛、脸部朝向、头部、鹿角和围巾的细微变化表达。禁止旋转整个精灵来伪造视线方向。四个正方向必须在正常显示尺寸下无歧义。

## 7. 制作流程

### 7.1 角色母版

先从多张本地参考图制作一张标准全身正面母版，固定脸型、刘海、鹿角、蝴蝶结侧别、围巾、服装、身体比例、线宽和颜色。母版未通过用户检查前不制作动作行。

### 7.2 动作行生成

- 每个状态制作成一个连贯的完整帧族。
- 默认使用带参考图的图像生成流程；如普通生成无法维持原画风，可按用户授权调用 `generating-with-shoubanhua` 进行范围受限的母版或整行动画补绘。
- 每次补绘必须附带角色母版和该状态的本地参考图。
- 不把来自不同风格或不同角色比例的孤立单帧拼成一行。
- `running-left` 因蝴蝶结和角色结构不对称而独立制作，不使用简单水平镜像。

### 7.3 确定性处理

生成结果只负责视觉内容。程序化处理负责：

- 帧组识别和裁切。
- 统一角色显示尺度和基线。
- 清理背景并生成透明像素。
- 检查裁切、重叠、内部透明孔洞和边缘污染。
- 按固定格子和行序组装最终图集。
- 输出 WebP、联系表、逐行动画预览和验证 JSON。

禁止要求图像模型直接生成完整 8×11 最终图集。

### 7.4 修复策略

- 身份、画风或动作失败时，只重做失败的完整动作行。
- 一个方向姿势失败时，重做包含它的完整方向行，不直接粘贴单个修补格。
- 纯裁切、注册或透明边缘问题优先确定性修复；视觉内容错误必须重新补绘。
- 任何修复都要重新生成该行预览并再次进入总览 QA。

## 8. 验证与完成标准

### 8.1 结构验证

- 图集尺寸严格为 1536×2288。
- 单元格严格为 192×208。
- `pet.json` ID 为 `kano--scarbal486`，并设置 `spriteVersionNumber: 2`。
- 所有有效格非空，未使用格完全透明。
- 输出格式和路径可由 Codex 正常读取。

### 8.2 视觉验证

- 所有行保持同一角色身份、比例、轮廓、颜色和渲染风格。
- 动作循环中不存在明显尺寸跳变、位置跳动、裁断或姿势倒放。
- 待机不是静态重复帧。
- 左右移动方向、朝向和步态正确。
- 任务进行中不是字面意义的跑步。
- 不出现漂浮文字、问号、UI、速度线、落地阴影或脱离身体的特效。
- 16 个方向形成连续顺时针环视，四个正方向无歧义。

### 8.3 本机验证

将 `pet.json` 与 `spritesheet.webp` 安装到：

```text
%USERPROFILE%\.codex\pets\kano--scarbal486\
```

重启或刷新 Codex 后选择该宠物，实际触发并检查待机、移动、招呼、跳跃、失败、等待、执行和审查状态。

### 8.4 用户验收

向用户展示：

- 标准 9 行联系表。
- 16 方向检查图。
- 每个状态的动画 GIF。
- 最终宠物在 Codex 中的实际截图或录屏证据。

只有用户确认画风和动画均无明显差距后，才创建成品 Release。

## 10. 成功判定

本项目成功需要同时满足以下条件：

1. 私有 GitHub 仓库存在，设计、成品和 QA 资料可追踪。
2. v2 图集和清单通过确定性验证。
3. 9 个标准状态均为真实、连贯的逐帧动画。
4. 16 个方向语义正确且循环连续。
5. 全部图像在正常宠物尺寸下保持原表情图的鹿乃画风。
6. 本机 Codex 可安装、选择并正常播放。
7. 用户完成最终视觉验收。
